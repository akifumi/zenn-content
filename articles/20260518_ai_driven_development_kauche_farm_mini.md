こんにちは！[akifumi](https://x.com/akifumifukaya) です。

最近、LINEミニアプリ「カウシェファームミニ」を **AI 駆動を前提とした並列開発** で1人・2ヶ月でリリースしました。
本記事では、カウシェファームミニでチャレンジした開発手法を共有したいと思います。

# 全体像

今回は1人チームでの新規開発だったため、**AI 駆動を前提とした開発手法** の検証も含めて開発を進めました。実際に取り組んだ開発フローは、次のとおりです。

1. PRD をリポジトリに配置
	- コードと同じリポジトリで管理
2. PRD から実装計画を生成
	- 後述の `/impl-plan-from-prd` スキルを活用して、PRD から実装計画を自動生成
	- 実装計画も同じリポジトリで管理
3. 実装計画をもとに、Agent Teams で並列開発
	- 各エージェントが独立した環境で協調しながら、同時並行で開発・PR 作成
	- 1回の指示で 5 ~ 15 件程度の PR を作成
4. PR ごとに AI が CI 上でレビューを実施
	- PRD / 実装計画 / Backend / Frontend など、全領域で AI Review
	- 1人開発のため、基本的に AI Review のみでマージ
5. PR をマージ
6. 3 に戻り、後続作業へ

PRD・設計（DesignDoc）・実装計画・実装・レビューまでの一連の工程を **AI 駆動のフローで構築したことで、並列開発を極限まで高める** ことができました。工夫点について、順に紹介します。

# 工夫点
## 工夫1: PRD・設計・実装計画など、全てのドキュメントをコードと同じリポジトリで管理する

カウシェの開発では、PRD や設計ドキュメントを Notion で管理することが多いです。
しかし、今回は AI 開発を前提とした並列開発を最大化するために **「ドキュメントをコードの近くに置くのが最も効率的なのではないか」** という仮説のもと、PRD・設計・実装計画をコードと同じリポジトリで管理することにしました。

カウシェファームミニでは、コードと同じリポジトリの `docs/web/farm-line/` 配下に全ドキュメントを配置しました。

```
├── docs/web/farm-line/                         # LINEミニアプリのドキュメント
│   ├── 01-prd/
│   │   ├── 1-0-prd-line-mini-app-mvp.md       # 全体像
│   │   ├── 1-1-crop-selection.md              # 作物選択
│   │   ├── 1-2-collect-water.md               # 水の獲得
│   │   ├── 1-3-give-water.md                  # 水やり
│   │   ├── 1-4-harvest.md                     # 収穫
│   │   └── ...
│   ├── 02-architecture.md                     # アーキテクチャ
│   ├── 03-farm-shared-design.md               # 共通モジュール設計
│   ├── 04-frontend-implementation-plans/      # Frontend 実装計画
│   └── 05-backend-implementation-plans/       # Backend 実装計画
└── web/farm-line/                             # LINEミニアプリのコード
```

ドキュメントとコードを同じリポジトリで管理することで、以下のメリットを得ることができました。

- **ドキュメントから、設計・実装計画・実装の流れがスムーズに**
	- MCP などで外部ツールに接続する必要なく、Claude Code から直接ドキュメントの参照が可能
	- より簡易かつ高頻度にドキュメントを更新できる
	- ドキュメントもコード同様に git でバージョン管理可能
- **AI がドキュメントとコードを横断して参照しながら作業を進行**
	- 設計や実装の過程で、AI がドキュメントを参照して整合性を確認しながら作業を進めることができる
	- 早期に軌道修正しながら、開発を進行
- **ドキュメントの変更にも開発ワークフローを適用**
	- ドキュメント修正もコード同様に、CI 上で AI Review を発火
	- 考慮漏れがないか、実装が可能な状態か、並列開発しやすい構造か、などを PR Review 時点で検知・フィードバックできる
	- AI Review の結果から、PR 作成時点で修正可能

## 工夫2: PRD から実装計画を生成する `/impl-plan-from-prd` スキルを作成

PRD から設計・実装計画の作成も AI で自動化しました。PRD が追加・更新されるたびに、設計・実装計画を更新する作業を繰り返していたため、`/impl-plan-from-prd` でスキル化しました。

このスキルは、**PRD を並列で読み込み、実装計画書（PR 分割戦略・依存関係・並列化戦略）を一括生成** します。
以下のコマンドを実行して、実装計画を更新します。
```
/impl-plan-from-prd \
  --prd_files "docs/web/farm-line/01-prd/" \
  --impl_plan_path "docs/web/farm-line/04-frontend-implementation-plans/" \
  --mode update
```

スキル内部では、以下の5つのフェーズを Subagent で並列実行しています。

1. **PRD 分析** — PRD ごとに Subagent を起動し、ユースケース・API・エラー・ロギングを抽出
2. **既存計画分析** — 既存の実装計画書を Explore Agent で分析
3. **最適化戦略立案** — Plan Agent が PR 分割・依存関係・クリティカルパスを設計
4. **計画書生成** — 機能ごとの計画書を生成
5. **一貫性検証** — セクション番号・用語・依存関係の整合性を全文書横断でチェック

上記のスキルで実装計画を作成する際、最も意識した点は **並列化の最大化** です。スキルが PR の依存関係グラフをつくり、どの PR を並列で進められるか、最速で実装するためにどの順番で着手するべきか、などを思考して実装計画を作成します。これが次の Agent Teams による並列実装につながります。

## 工夫3: Agent Teams で複数機能を並列実装

次は、実装計画からの並列実装です。Agent Teams を活用し、メインエージェント（チームリーダー）配下に複数の実装者エージェントを並列に配置して開発を進めました。

Subagent で単に並列実装するのではなく、Agent Teams を活用することで、実装者エージェント同士が相互レビューし合うようにしました。そうすることで、エージェント間で作業内容が重複することを防ぎ、生成されるコードの品質も向上させることができました。

開発中は以下のようなプロンプトを実行し、複数の機能を一気に開発しました。カウシェファームミニでの開発では、1回の指示で 5 ~ 15 件程度の PR が作成されました。

```
あなたはカウシェのエンジニアスペシャリスト集団のチームリーダーです。
`docs/web/farm-line/` の実装計画に基づいて、後続の実装可能なところの実装を進めてください。
並列化・効率化のために、agent teams を活用して実施してください。
実装の過程で、作業範囲が被っていないか、実装内容が重複していないか、非効率になっていないか、などを各作業の実装者同士が相互レビューを実施したり、チームリーダーとして各実装者の成果物をレビューしたりして、作業内容が問題ないかを適宜確認をしながら作業を進めてください。

作業分割の観点から、child branch を作成しながら作業を進めてもらって構いません。
各 branch で作業が完了したら、Pull Request を作成してレビューを待ってください。
その際、Auto Merge されないように hold ラベルを付与してください。
ただし、branch の削除や Pull Request マージ/クローズは絶対にしないでください。

以下の開発環境を活用してください。
`../working-a` ... `../working-z`
```

開発中はスキル化できなかったのですが、今後スキル化しようと考えています。

## 工夫4: AI Review の徹底

当たり前ではあるのですが、1人開発ではコードレビューが課題になります。レビュアーとなってくれる人がいないため、AI Review を徹底しました。

PR の対象ファイルに応じて、各々のレビュー観点に特化した AI Review を実行するワークフローを構築しました。

| Workflow                       | トリガー            | レビュー観点                                        |
| ------------------------------ | --------------- | --------------------------------------------- |
| `ai-review-prd.yaml`           | PRD ファイル変更時     | 仕様の網羅性、一貫性、ユースケース定義                           |
| `ai-review-impl-plan.yaml`     | 実装計画変更時         | PR 分割の妥当性、依存関係                                |
| `ai-review-backend.yaml`       | Backend コード変更時  | Go 実装、proto 定義整合、エラー設計                        |
| `ai-review-web-farm-line.yaml` | Frontend コード変更時 | コンポーネント設計、コンポーネント共通化、TypeScript 実装、LIFF 特有の挙動 |
| `ai-review-ai-codes.yaml`      | `.ai/` 配下変更時    | AI Rules・プロンプト・スキル定義の整合性                      |

レビュー観点を領域別に専門化することで、それぞれの領域で深く適切なフィードバックが得られます。

さらに、AI Review が **自分で学習し、精度を高めていく自己改善の仕組み** も組み込んでいます。以下の3つが連動することで、レビューが自動で改善していきます。

- **`web-farm-line-learned-rules.md`**
	- 過去のレビューで人間が修正した内容を蓄積する学習ルールファイル
	- 各ワークフローで参照することで、**同じ指摘漏れを起こさない**
- **`ai-review-web-farm-line-merge-insight.yaml`**
	- PR がマージされるたびに、その PR から「どんな指摘があり、どう修正されたか」を蓄積
	- 後続で **同じような指摘をしない**
- **`ai-review-self-improve-web-farm-improve.yaml`**
	- 抽出された insight を集約し、学習ルールを継続的にアップデート

上記により、開発するごとに **AI Review が自分自身を進化させていく** 仕組みを構築しています。

# 結果
## 成果: 1日あたり平均PR作成数 15.8 件、1人・2ヶ月でリリース

前述の工夫もあり、開発ピークだった2026年4月の **1日あたり平均PR作成数は 15.8 件** でした。1日での最大PR作成数は 39 件に達した日もあります。

実装すべき機能は決して少なくありませんでしたが、結果としてLINEミニアプリ「カウシェファームミニ」を1人・2ヶ月でなんとかリリースすることができました。

AI を前提とした開発手法、かつ並列開発を極限まで高める工夫によって、少人数かつ短期間での開発を実現できました。

# まとめ

LINEミニアプリ「カウシェファームミニ」の開発でチャレンジした、**AI 前提の開発手法と並列開発を最大化する工夫** を紹介しました。

簡単にまとめると以下です。

1. **PRD・設計・実装計画など、全てのドキュメントをコードと同じリポジトリで管理**
	- AI がドキュメントとコードを横断して参照でき、CI 上で AI Review にも適用可
2. **`/impl-plan-from-prd` のスキル化**
	- PRD から並列化を最大化した実装計画を自動生成
3. **Agent Teams による並列実装**
	- メインエージェントをチームリーダーとして、配下に複数の実装者エージェントを配置して並列実装
	- エージェント同士が相互レビューし合うことで、作業の重複を防ぎ、生成コードの品質も向上
4. **AI Review の徹底**
	- 少人数（1人チーム）のため、AI Review を徹底して進行
	- レビュー観点を領域別に専門化して、深いレビューを実施
	- `learned-rules` / `merge-insight` / `self-improve` による自己改善ループによって、開発が進むにつれて AI Review が向上する仕組みを構築

これらの工夫により、開発ピークだった2026年4月は **1日あたり平均PR作成数 15.8 件** を達成し、LINEミニアプリ「カウシェファームミニ」を1人・2ヶ月でリリースする成果につながりました。

AI を前提にした開発・並列開発の最大化・少人数での開発促進に取り組もうとしている方々の参考に少しでもなれば幸いです。
